1. What it is

Fabric-X re-architects Fabric into microservices: endorser / validator / committer plus Arma (routers, batchers, consenters, assemblers). There is no chaincode for the normalized KV cell — the adapter is the contract: it builds the read/write set the committer applies.

REST / Token SDK path retired here

Older docs described blocking HTTP token issue/transfer and a custom /kv FSC view. That path is gone. Normalized modes use the same configs/normalized/*.yaml as everyone else over native gRPC.

2. How we measure it

  • Submit — sign namespace payload (ECDSA-P256) → broadcast the same envelope to all four Arma routers. T2 = first SUCCESS ack (real platform ack — comparable to Fabric T2 in kind).
  • Finality — sidecar deliver stream :4001. T3 when the block shows COMMITTED.
  • kv-read — QueryService.GetRows on :7001 (no order/commit).
TxWrite → blind write ns "0" → Envelope → routers 6022/6122/6222/6322 (T2 = first SUCCESS) → Arma orders digest → assemblers → committer → Postgres → deliver :4001 → T3
Broadcast all four routers

A single non-primary router adds ~10 s FirstStrike delay. connection.env must list all four. Older one-router envs produce invalid latency.
