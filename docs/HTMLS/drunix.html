Drunix writes live NPCI’s Fabric 2.5.x fork — same Gateway API, disaggregated peer, YugabyteDB statedb. Writes work via a client-side JSON wrap.

state DB: Yugabyte (parity not held) Lite Peer + Committing Peer CFT / Raft only

1. What it is

Drunix keeps Fabric’s Execute-Order-Validate shape and the standard Gateway SDK surface, but splits the peer:

ChangeEffect
Lite PeerEndorse + gateway + broadcast only — never commits
Committing PeerValidate + commit to YugabyteDB
Validation ServiceStateless VSCC/MVCC offload
YugabyteDBDefault world state (SQL/JSONB)

No BFT path — Drunix only belongs in CFT comparisons against fabric-cft.

2. How we measure it

Adapter pkg/adapters/drunix wraps the Fabric adapter:

  • Endorse/submit against the Lite Peer (:7051).
  • Finality from the Committing Peer filtered-block stream (:7061) via UseCommitPeerEvents — Gateway Commit.Status() on the Lite Peer never fires.
  • Same T1/T2/T3 definitions as Fabric; only the wire path for T3 differs.
Client → Lite Peer (endorse + broadcast) → Raft orderer ↘ Committing Peer (validate + YugabyteDB) → T3

3. Write path — fixed (JSON wrap)

No longer blocked

Earlier diagnosis blamed sparse-block / lean envelopes. That WARN is benign. The real bug: Yugabyte’s statedb writer force-casts values to JSONB and panics on raw strings. The adapter now JSON-wraps write values in pkg/adapters/drunix/valuecodec.go (disclosed as a caveat). Verified: fail_rate 0 on smoke and successful probe-sweep holds.

raw 64 bytes  →  json.Marshal(string)  →  "\"hijklmnop…\""
chaincode PutState stores the JSON text; Query unwraps for the harness

Transfers already produce JSON balances — not re-wrapped.

4. Normalized vs actual

Normalized configs request LevelDB; the shipped Drunix network runs Yugabyte → state-db parity not held in the manifest. On-wire values are a few bytes larger than Fabric’s raw puts.

5. Status

Saturation ~500 offered; hold@450 → 450 confirmed TPS, fail_rate 0, e2e p50/p99 ~538/762 ms. Lower than fabric-cft: more containers, Yugabyte, LP→CP hop.
