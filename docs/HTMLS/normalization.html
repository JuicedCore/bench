Bench Overview Load path Fabric Drunix Fabric-X NeuChain Normalization

Normalization Same logical effect, same seed, same ladder — never mix normalized and native numbers in one ranking.

1. Why “same code everywhere” fails

Fabric speaks chaincode. Fabric-X speaks namespace RW-sets. NeuChain speaks YCSB over ZMQ. A harness that only issued “chaincode invoke” would leave blank cells. We normalize the logical effect (write this key, transfer between accounts) and map each effect onto the platform’s native primitive — then attach caveats when the mapping is imperfect (ADR-010).

4. What we hold identical

  • YAML load block (ladder, windows, seed, key space, value size, finality wait)
  • Resource budget from the profile (split by role weights across containers)
  • Fabric-family orderer_batch anchor (ADR-011)
  • Requested state DB = LevelDB for normalized (ADR-012)

kv-write across families is the main comparable cell with state-DB and block-cutting caveats. Do not rank NeuChain reads against Fabric Evaluate. Do not mix normalized and native (token/UTXO) runs.

6. Native vs normalized

ADR-009: both modes exist. Normalized = fair comparison (configs/normalized/, one file per mode). Native = platform ceiling (configs/native/<platform>.yaml, normalized: false, kv-write). A second native preset, configs/native-kv-mixed/, uses the same levers at 50% reads — do not rank it against the kv-write ceiling. Fabric-family mixed reads are Evaluate / QueryService and never hit the orderer. Fabric-X native is still the gRPC path; Token SDK / UTXO is not implemented (old REST token configs were removed with that path).

make bench PROFILE=local-32gb \
  PLATFORMS="fabric-cft fabric-bft drunix fabricx neuchain" \
  CONFIGS=configs/native

make bench PROFILE=local-32gb \
  PLATFORMS="fabric-cft fabric-bft drunix fabricx neuchain" \
  CONFIGS=configs/native-kv-mixed
